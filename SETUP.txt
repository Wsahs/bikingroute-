Recommended arrangement
1. Use the existing Supabase project for database, optional rider accounts, and server
   functions. Keep the Google server key in Edge Function Secrets.
2. Browser maps require a separate website-restricted Google key. It is visible
   to browsers by design; storing it in Supabase cannot make it a server secret.
   Verify what the downloaded Demo Key supports before using it in either role.
3. Use the existing GitHub repository for source code, tests, and schema migrations.
   Exclude API keys, local env files, generated address inventories, and map caches.
4. Host the current Python routing service separately or deliberately migrate it;
   creating a Supabase project does not automatically host this Python service.
5. Host the browser frontend on an HTTPS site. Native iPhone builds need Xcode,
   Apple signing setup, and a physical-device/simulator test before distribution.

Not yet solved by infrastructure
- Complete address-to-path connectivity and sidewalk coverage.
- Production quality navigation maneuvers and independent street-gap alternatives.
- Data source attribution, refresh jobs, coverage checks, and deployment monitoring.

Credentials
Use the Supabase Dashboard's Edge Function Secrets or a local CLI env-file upload.
Never paste the key into SQL, a public table, README, screenshot, or Git history.
A successful setup must verify the secret is configured without returning its value.

GOOGLE AUTOCOMPLETE VERIFICATION
Autocomplete now updates after each nonempty edit (250 ms debounce), with a
Google session token and explicit Place Details lookup on selection. Selected
coordinates use the correct Maps JavaScript lat/lng format. Stale selection
responses are discarded after further editing or swapping. Alternatives are
sorted by returned distance; no global shortest-path guarantee is made.
